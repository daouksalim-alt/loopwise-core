# Independent use and feedback

Loopwise Core is looking for developers building small browser games, coding exercises, or recreational learning tools who can try one generator in a project of their own.

Start with the [integration trial](QUICKSTART.md) and [share your feedback](https://github.com/daouksalim-alt/loopwise-core/issues/new?template=integration-feedback.yml). A failed integration or a clear explanation of why this library is not useful is valuable feedback.

## Current evidence

As of October 31, 2026, no independent integrations have been verified. The parent Loopwise application, browser demo and offline starter are maintainer-owned examples. Automated tests and maintainer smoke tests are validation, not outside users.

The first milestone is three independent integration attempts with concrete feedback, including unsuccessful attempts. This is a goal, not a forecast or a claim that participants have been recruited.

## How to assess a report

1. Separate trying the demo, opening the starter, running a prototype and using the library in an existing project. Preserve the developer's actual stage.
2. Reproduce the reported behavior or inspect the public example. If no public evidence is available, record it as a self-report rather than independently verified use.
3. Address a reproducible blocker with a focused fix or documentation change. Link the report and the relevant revision.
4. List a public project in a showcase only with permission. Never publish private correspondence, personal contact details, private code or sensitive records.
5. Keep unsuccessful attempts in the record. Do not count maintainer examples, agent tests, duplicate reports, stars, forks, bot traffic or page views as independent integrations.

## Feedback priorities

Which installation step was unclear? Does seeded replay help reproduce a real bug? Are the question fields sufficient for the developer's renderer? Is content variety a limiting factor? Would a smaller or different API be easier to use?

Choose the next feature from observed needs. Do not add frameworks, new games or translations solely to make the repository look busier.
